# 📚 DocuChat — Chat With Your Documents (RAG)

A small, transparent **Retrieval-Augmented Generation** system built from scratch in Python.
Ask questions about your own documents and get answers with **citations** pointing to the
exact passages used. No vector-DB or framework magic: every step is a few readable lines.

It runs **fully offline** out of the box (TF-IDF retrieval + extractive answers) and upgrades
automatically when you add optional pieces:

| Component | Default (no setup) | Optional upgrade |
|---|---|---|
| Retrieval | TF-IDF + cosine similarity | Dense embeddings (`sentence-transformers`) |
| Answer generation | Extractive: best matching sentences | Claude via the Anthropic API |
| Input files | `.txt`, `.md` | `.pdf` (`pypdf`) |

## How it works

```
 documents ──► load ──► chunk (paragraph-aware, overlap) ──► index (TF-IDF / embeddings)
                                                                   │
 question ──► retrieve top-k passages ◄────────────────────────────┘
                    │
                    ├─ best score below threshold? ──► "I couldn't find that" (no LLM call)
                    └─ otherwise ──► generator (Claude or extractive) ──► answer + [1][2] citations
```

Design choices worth noting:
- **Paragraph-aware chunking** keeps headings attached to their text; overlap protects answers that straddle a boundary.
- **Abstention**: if retrieval confidence is low, the system says it does not know instead of guessing (and saves an API call).
- **Grounded prompt**: the LLM is told to answer only from numbered context and cite it.
- **Evaluated**: retrieval quality is measured, not assumed (see below).

## Quick start

```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m docchat ingest                              # index data/docs (sample company handbook)
python -m docchat ask "How many days of annual leave do I get?"
python -m docchat chat                                # interactive loop
streamlit run app/streamlit_app.py                    # web UI with uploads and source viewer
pytest -q
```

Use your own files: `python -m docchat ingest --docs path/to/folder`

### Optional upgrades

```bash
pip install -r requirements-optional.txt

export ANTHROPIC_API_KEY=your-key        # answers now generated by Claude (see .env.example)
python -m docchat ingest --retriever embeddings
```

Example output (offline mode):

```
$ python -m docchat ask "What should I do if my laptop is stolen?"

If a laptop or phone is lost or stolen, report it to the IT helpdesk immediately so it can be wiped remotely. [1]

Generator: extractive (offline)
  [1] security.md  (score 0.15)  ## Devices Company laptops are encrypted by default ...
```

## Evaluation

`python -m docchat eval` checks whether the correct source document appears in the top results
for 26 questions (`data/eval/qa.json`): 20 that reuse the documents' own wording and 6 that are
deliberate **paraphrases** with little word overlap.

| Retriever | hit@1 | hit@3 | MRR |
|---|---|---|---|
| TF-IDF (default) | 0.92 | 0.96 | 0.950 |
| Embeddings | _run `python -m docchat eval --retriever tfidf embeddings` and fill in_ | | |

The two misses are both paraphrases ("time off after having a baby", "confirmed in my job"):
keyword matching cannot connect them to "parental leave" and "probation". That is exactly the
gap dense embeddings are meant to close, so compare the two retrievers on your machine and
record the result here.

## Project structure

```
docuchat-rag/
├── docchat/
│   ├── loader.py      # read .txt / .md / .pdf
│   ├── chunker.py     # paragraph-aware chunking with overlap
│   ├── retriever.py   # TfidfRetriever, EmbeddingRetriever
│   ├── llm.py         # ClaudeGenerator, ExtractiveGenerator, prompt
│   ├── rag.py         # RAGPipeline: ingest / save / load / ask
│   ├── evaluate.py    # hit@k and MRR
│   ├── cli.py         # ingest | ask | chat | eval
│   └── config.py
├── app/streamlit_app.py
├── data/docs/         # sample handbook (5 files)
├── data/eval/qa.json  # evaluation questions
├── tests/
└── requirements.txt  requirements-optional.txt  Makefile  .env.example
```

## Limitations and next steps
- The extractive fallback returns existing sentences; it cannot combine facts across passages. Use Claude for that.
- Evaluation measures retrieval only. Add answer-quality checks (e.g. LLM-as-judge for faithfulness) next.
- Ideas: hybrid search (TF-IDF + embeddings), a re-ranker, conversation memory for follow-up questions, a FAISS/Chroma index for large corpora, streaming answers.
